1 Cel

Wirtualny pracownik działający niezależnie od laptopów zespołu: cyklicznie pobiera zadania, uruchamia skrypty i narzędzia, obsługuje aplikacje (w tym Power BI, Office, przeglądarkę), waliduje wyniki i zostawia pełny ślad audytowy każdej decyzji.

Zasada nadrzędna: najpierw udowodnić na małym (pobranie zadania, poprawne wykonanie, samodzielna walidacja, audyt, bezpieczne zatrzymanie), a dopiero potem rozszerzać uprawnienia i zakres. Nie budować od razu wszechstronnego pracownika z dostępem do całej firmy.

2 Architektura

Rdzeń w Pythonie, stan w lokalnym SQLite, wszystko chodzi na jednej maszynie (Windows Server 2022 / Windows 11). Model AI planuje i ocenia; skrypty wykonują powtarzalne czynności.

3 Przepływ zadania

zadanie (Projectly / notatnik / dashboard)
   │
   ▼  kontrola treści (prompt injection?) ── wykryto → eskalacja
   ▼  klasyfikacja ryzyka: zielone / żółte / czerwone         [decyzja: pawel]
   ▼  routing do właściciela
   ▼  wykonanie (executor) — tylko w granicach kontraktu       [decyzja: patrycja]
   │      • zielone bez efektu → auto-done
   │      • żółte / zielone z efektem → BRAMKA JAKOŚCI
   ▼  bramka: Bartek(regresja) Franek(testy) Oskar(wizja) Bożena(odbiór)  [decyzja: gustaw]
   │      • przeszło → done
   │      • nie / czerwone → eskalacja jako zadanie dla człowieka        [decyzja: pawel]
   ▼  każdy krok → dziennik decyzji (state.db) → widok „Zadania" w dashboardzie

Fail-closed: przy niepewności agent nie wykonuje działania nieodwracalnego — zapisuje stan i eskaluje. Czerwone (publikacja, budżet, usunięcie danych) zawsze do człowieka.

5 Bezpieczeństwo

MechanizmOpis
Kontrakt uprawnień jestModel uruchamia tylko zarejestrowane narzędzia, w granicach allowed_roots. Reszta = odmowa (fail-closed).
Klasy ryzyka jestZielone (auto) / żółte (auto w granicach polityki, walidatory) / czerwone (zawsze człowiek). config/approval_policy.yaml.
Panel operatora jestPAUSE (wstrzymaj bez utraty stanu) / STOP (wyłącznik awaryjny) / START. Wszystkie pętle respektują.
Ochrona sekretów jestKlucze nigdy w repo/logach/zrzutach; maskowanie pól. Sekrety w app/secrets/ (poza gitem).
Ślad audytowy jestKażda decyzja w SQLite: kto/co/dlaczego/model/koszt. Eksport CSV/JSONL do analizy.
Kontrola prompt injection jestTreść zewnętrzna sprawdzana przed klasyfikacją; wykrycie zawsze eskaluje.

6 Dashboard

python app/dashboard.py → http://127.0.0.1:8787/ (tylko localhost). Zawiera:

  • Pasek operatora — stan (Pracuje/Wstrzymany/Zatrzymany), kolejka, koszt, zdrowie, limity Claude (5h/dziś) i szacowaną liczbę pozostałych zadań.
  • Dodaj zadanie — formularz (treść, ryzyko, ścieżka PBIP), przetwarzane od razu lokalnie.
  • Zadania — grupowane po zadaniu, rozwijana oś czasu: czas → agent → krok → decyzja → dlaczego.
  • Skrypty i harmonogram — edycja interwałów, „uruchom teraz", historia przebiegów z pełnym wyjściem.

8 Limity i koszt

usage_monitor.py czyta to samo źródło co statuslinia terminala (~/.claude/powerline/usage/today.json): koszt okna 5h i dziś, oraz estymację ile zadań jeszcze wobec ustawianego budżetu. cost_tracker.py pilnuje dziennego limitu i wyzwala kill switch po przekroczeniu.

Twardy limit subskrypcji (dokładny sufit 5h/tygodnia) nie jest dostępny programowo — estymacja jest wobec budżetu, który ustawiasz, nie wobec ukrytego limitu Anthropic.
