Instalacja maszyny

Jak postawić wirtualnego pracownika na nowej maszynie. Instalacja jest bezobsługowa: uruchamiasz i możesz wrócić później, nic się nie zatrzyma na pytaniu.

📦 Czego potrzebujesz

🖥️ Maszyna

Windows Server 2022 albo Windows 11. Dedykowana, włączona całą dobę, ze stałym internetem i uprawnieniami administratora.

🔑 Konta

Microsoft 365 Business Standard (Office, poczta, SharePoint) oraz subskrypcja Claude do logowania w Claude Code.

🧩 Dostępy

Klucz do Projectly. Reszta (Microsoft Graph, MailerLite, Meta Ads) opcjonalnie, zależnie od tego, co bot ma robić.

⚙️ Instalacja krok po kroku

  1. Pobierz projekt

    Na zupełnie pustej maszynie otwórz PowerShell jako administrator i wklej jedną linię:

    $s="$env:TEMP\postaw.ps1"; irm https://raw.githubusercontent.com/odczarujpowerbi/wirtualny-pracownik/main/instalacja/skrypty/postaw-od-zera.ps1 -OutFile $s; powershell -ExecutionPolicy Bypass -File $s

    Jeśli repozytorium już jest na maszynie, przejdź od razu do kroku 2.

  2. Uruchom instalator

    W folderze instalacja kliknij prawym na Przygotuj-srodowisko.bat i wybierz Uruchom jako administrator. Zainstaluje po kolei: Git, Python, Node.js, Claude Code, VS Code, Office, aplikacje (Power BI, Teams, Outlook, Chrome), zależności, autostart i test końcowy z raportem.

    Każdy krok sprawdza, czy dana rzecz już jest, więc ponowne uruchomienie jest szybkie.

  3. Wpisz dostępy

    Uruchom python bootstrap_init_secrets.py. Utworzy plik na klucze i szkielety połączeń. Uzupełnij je wartościami.

    Dostępy nigdy nie trafiają do repozytorium. Leżą lokalnie w folderze poza kontrolą wersji.

  4. Zaloguj się na konta

    Osobny, szybki krok po instalacji: instalacja/Zaloguj.bat przeprowadza po kolei przez wszystkie logowania.

  5. Zarejestruj rolę maszyny

    python bootstrap_register.py dev (albo inna rola). Maszyna zapisuje swoją rolę i ogłasza się w Projectly pierwszym statusem.

🔑 Co wpisać w dostępy

KluczDo czego
PROJECTLY_API_KEY
PROJECTLY_BASE_URL		 Wymagane. Bez tego bot nie ma skąd brać zadań i pracuje na danych testowych.
ANTHROPIC_API_KEY Opcjonalne, gdy logujesz się subskrypcją przez claude login. Zapasowa droga do modelu.
MS_GRAPH_* Opcjonalne. Wysyłka poczty i zapis na SharePoint.
Pliki połączeń w secrets/mcp/ Po jednym na integrację: Projectly, Zoho CRM, Zanfia.
Sprawdź, zanim uznasz że gotowe python secrets_audit.py pokazuje, czego kod szuka, co jest wypełnione i czego brakuje. Nigdy nie wypisuje samych wartości. Osobno: python graph_verify.py (poczta, nic nie wysyła) i python sharepoint_verify.py (dostęp do dokumentów).

▶️ Uruchomienie

Przy zalogowaniu startuje tylko nadzorca (start-nadzorca.bat). To on odpala boty, i tylko te, które są włączone w Projectly. Nie trzeba niczego dodawać do autostartu ręcznie. 

# normalna praca: nic nie robisz, nadzorca startuje sam
start-nadzorca.bat

# diagnostyka: jeden bot ręcznie, z pominięciem nadzorcy
start-agent-dev.bat        albo -checker / -marketing / -zarzad

# podgląd na maszynie
start-dashboard.bat        http://127.0.0.1:8787/

Sterowanie botami opisane jest w sekcji Sterowanie i nadzór.

🩹 Gdy coś nie działa

ObjawCo zrobić
Aplikacje się nie zainstalowały Na Windows Server często brakuje menedżera pakietów. Instalator próbuje go doinstalować sam, ale warto sprawdzić raport końcowy.
claude nie działa w terminalu Dodaj C:\Users\<user>\.local\bin do zmiennej PATH i otwórz nowy terminal.
Bramka jakości odsyła wszystko Sprawdź, czy jesteś zalogowany w claude. Bez modelu ocena nie działa i celowo odmawia zamiast przepuszczać.
Bot nie widzi zadania, które dodałeś python queue_verify.py pokazuje kolejkę każdej roli i luki w uprawnieniach kont AI do projektów.
Chcesz sprawdzić, czy repo jest zdrowe po zmianie python self_check.py uruchamia wszystkie testy dymne i wypisuje wynik.
Dalej: Mapa repozytorium.
