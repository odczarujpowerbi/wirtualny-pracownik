2 app/ — kod

Folder/plikCo jest
config/Konfiguracja firmy — edytowalna bez zmiany kodu. approval_policy.yaml (klasy ryzyka), tool_contracts.yaml (allowlisty), models.yaml/model_tiers.yaml (rejestr modeli), odbior_ustalenia.yaml (co blokuje odbiór), business_context.yaml, validation_gate.yaml, schedule.yaml.
kontekst/Wiedza o firmie: firma-podstawy.md, marka-*.md, projekty/*.md, persony/<marka>/*.md (buyer persony). Patrz Kontekst firmy, Buyer persony.
persony_botow/Persony BOTÓW (jak mają oceniać), np. bozena_biznes.md. Nie mylić z kontekst/persony/ (buyer persony klientów) — nazwy rozdzielone po realnej kolizji.
skills/Wiedza "jak dobrze użyć" danego źródła/integracji, np. web_research_operations.yaml (per-hosta wskazówki dla web_answer).
inbox/zadania.txtNotatnik zadań (lokalna ścieżka, patrz Skąd zadania).
mock_data/Dane testowe (przykładowy PBIP, przykładowe zadania) do pracy bez żywych kluczy.
templates/email/Szablony maili (.md) do email_draft_generator.py.
secrets/ poza gitem.env + mcp/*.json — klucze i tokeny. Nigdy w repo.
runs/ poza gitemStan lokalny: state.db, run_history.jsonl, heartbeat, zrzuty, pobrana treść z internetu (runs/web/).

Rdzeń pipeline'u

runner_loop.pyGłówna pętla: klasyfikacja → routing → wykonanie → poprawka → bramka → eskalacja/zamknięcie.
executor.pyRozpoznaje typ zadania i woła właściwego workera (PBIP, web fetch, MailerLite, Zanfia).
task_thinker.pyWołanie modelu (Claude Code → SDK → Ollama), z poziomem z model_registry.py.
tool_registry.pyKontrakt uprawnień — allowlisty plików i domen.
model_registry.pyRejestr modeli i poziomów (patrz Modele i koszty).
kontekst_firmy.pyDobór wiedzy o marce/projekcie/personie do promptu.
poprawka_materialu.pyNanoszenie zastrzeżeń bramki na materiał (pętla poprawek).
state_store.pyZadania + dziennik decyzji w SQLite.
