Wirtualny Pracownik AI — instrukcja

Jak zainstalować i uruchomić narzędzie na nowej maszynie, co wpisać w dostępy i gdzie klikać. Po ludzku, w punktach. Pełny opis techniczny: dokumentacja.html. Mapa pokrycia celu: przeplyw.html.

0 Czego potrzebujesz

  • Maszyna: Windows Server 2022 albo Windows 11 (dedykowana, włączona 24/7, stały internet).
  • Konto Microsoft 365 Business Standard (do aktywacji Office i pracy w chmurze).
  • Subskrypcja Claude (do logowania w Claude Code) oraz klucze: Projectly, opcjonalnie inne.
  • Uprawnienia administratora na maszynie (część instalacji tego wymaga).

1 Instalacja środowiska

Instalacja jest bezobsługowa — uruchamiasz i możesz wrócić następnego dnia. Nie zatrzymuje się na logowaniach.

  1. Pobierz projekt

    Maszyna zupełnie pusta (bez repo, bez gita)? Otwórz PowerShell jako administrator i wklej jedną linię — pobierze gita, sklonuje repo i uruchomi cały instalator:

    $s="$env:TEMP\postaw.ps1"; irm https://raw.githubusercontent.com/odczarujpowerbi/wirtualny-pracownik/main/instalacja/postaw-od-zera.ps1 -OutFile $s; powershell -ExecutionPolicy Bypass -File $s

    Jeśli repo już jest na maszynie — przejdź do kroku 2.

  2. Uruchom instalator

    Wejdź do folderu instalacja, kliknij prawym na Przygotuj-srodowisko.bat → Uruchom jako administrator.

    Zainstaluje po kolei: Git, Python, Node.js, Claude Code, VS Code + rozszerzenie, Office, aplikacje (Power BI, Obsidian, Teams, Outlook, Chrome), Terminal + profile Claude, statuslinię limitów, modele lokalne, OneDrive, zależności, autostart 24/7, test i raport. To potrwa (Office i modele to kilka GB).

    Każdy krok sprawdza, czy dana rzecz już jest — ponowne uruchomienie jest szybkie (pomija to, co zainstalowane).

2 Wpisz dostępy (secrets)

Sekrety nigdy nie trafiają do repozytorium. Leżą lokalnie w app\secrets\.

Plik app\secrets\.env — klucze

KluczCo wpisać / skąd
ANTHROPIC_API_KEYKlucz API Anthropic (opcjonalny, jeśli logujesz się subskrypcją przez claude). Główny model.
PROJECTLY_API_KEYKlucz do Projectly (kolejka zadań). Bez niego agent działa w trybie mock (dane lokalne).
PROJECTLY_BASE_URLAdres API Projectly (domyślny już wpisany).
MS_GRAPH_CLIENT_ID / SECRET / TENANT_ID / MAILBOXOpcjonalnie — realna wysyłka maila przez Microsoft Graph (rejestracja aplikacji w Azure AD).
OLLAMA_HOST / OLLAMA_VISION_MODEL / OLLAMA_TEXT_MODELOpcjonalnie — modele lokalne (domyślnie localhost:11434).

Folder app\secrets\mcp\*.json — integracje MCP

Po jednym pliku na integrację MCP: dziś zoho_crm.json, projectly.json, zanfia_courses.json. Uzupełnij w nich adres serwera/token wg konkretnej konfiguracji MCP.

Google nie ma jeszcze pliku w secrets — integracja Google Workspace nie jest zbudowana. Gdy powstanie, dojdzie tu service-account JSON. Na razie Google używasz przez przeglądarkę (krok 4).

3 Uruchom agenta

Agent startuje sam po zalogowaniu (autostart ustawia instalator). Ręcznie:

cd app
python job_scheduler.py        <- pętla 24/7 (pobiera zadania, klasyfikuje, waliduje)
python dashboard.py            <- podgląd: http://127.0.0.1:8787/

W dashboardzie (na localhoście) masz: pasek sterowania (Pauza / Stop), kondycję i limity Claude, formularz Dodaj zadanie, oraz widok Zadania z osią czasu decyzji każdego bota.

4 Zaloguj się na konta

Osobny, szybki krok — po instalacji. Nie wszystko da się przez API, część idzie przez interfejs.

  1. Uruchom instalacja\Zaloguj.bat

    Przewodnik otworzy po kolei aplikacje/strony i zapyta, czy zalogowane.

KontoPo co

5 Aktualizacja i codzienne użycie

  • Nowy kod z GitHub: dwuklik aktualizuj-repo.bat w głównym folderze.
  • Podgląd pracy: python app\dashboard.py → http://127.0.0.1:8787/.
  • Zatrzymanie: przycisk Stop w dashboardzie (albo Pauza — wstrzymuje bez utraty stanu).
  • Nowe zadanie bez Projectly: formularz „Dodaj zadanie" w dashboardzie albo dopisz linię do app\inbox\zadania.txt.

6 Gdy coś nie działa

ObjawCo zrobić
Aplikacje / Terminal się nie zainstalowałyNa Windows Server często brak winget. Instalator próbuje go doinstalować; jeśli się nie uda — zainstaluj App Installer ze Sklepu albo aplikacje z bezpośrednich linków.
claude nie działa w terminaluDodaj C:\Users\<user>\.local\bin do PATH i otwórz nowy terminal. Instalator wykrywa tę ścieżkę automatycznie.
git pull zgłasza konflikt na schedule.yamlJednorazowo: git checkout -- app/config/schedule.yaml potem git pull. Od kolejnego pobrania problem nie wraca (plik jest lokalny, w repo jest szablon).
Bramka jakości wszystko eskalujeSprawdź, czy jesteś zalogowany w claude — bez modelu odbiór biznesowy nie działa i wszystko idzie do człowieka (celowo, fail-closed).
